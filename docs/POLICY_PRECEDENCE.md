# Policy precedence

1. Unsupported operation: block. No runtime input can enable a removed engine or external-dispatch capability.
2. Missing, invalid, expired or unusable policy/trust checkpoint: block content and retain restricted application controls.
3. Mandatory-category and security exclusions are invariant. No positive record can grant live content in this milestone.
4. Exact current, signed, nonrevoked bundled record with approved context and verified bytes: eligible for that record only.
5. Additional user restrictions subtract optional collections/resources. They never add eligibility. Valid reviewed support resources remain reachable.
6. Presentation rechecks eligibility for every article, result, saved item and tab title, and on policy/lifecycle changes.

Consumer, student, unknown-edition and private sessions use this same order. Unknown editions inherit student-like noncommercial/session restrictions. The edition is a packaging constant; there is no runtime switch. PIN, administrator, teacher, paid, temporary, custom-allow, debug advertising and old Guard flags are not approval inputs.

A resource destination, dependency, authentication endpoint and download are different capabilities. This version supports only plain bundled text and bundled app assets. A source URL or an ID found in an old bookmark is not a permission. `errorAllow` is no longer an allow outcome. Corrupt or stale settings are sanitized before exposure; core protection does not depend on successfully reading settings.

Revocation/sequence/time checkpoints can increase strictness and cannot be lowered by ordinary application updates. A production rollback must preserve previously known security restrictions and be independently designed/tested; no user-facing rollback exists.
