# Visual adaptations from the selected boards

The nine supplied boards and three mobile references remain the chosen direction. The implementation uses the original Wingman logo, semantic navy/blue/cyan roles, local ribbon painter, wide cards, conventional browser controls and light/dark themes. See [VISUAL_INDEX](VISUAL_INDEX.md) for reference-to-screen mappings.

- Reference names, example page content, prices, task progress and protection totals are not default production data. Empty Home/companion/Spaces and unavailable observation have deliberate real states.
- Website content stays native and dominant. Desktop browser chrome appears only with actual native capability. The web companion has a local-tool rail and explicit host-browser handoff scope.
- The companion uses a360-logical-pixel panel when sufficient website space remains; narrower windows use a sheet. Expanded browser chrome also falls back for short windows or large text.
- Mobile Home shortens the hero and exposes an active task's Continue action near search. Existing explicitly saved module order and visibility remain authoritative.
- Cards stack when width or200% text requires it. Labels, evidence and limitations may make screens taller than the concept artwork; important copy is not clipped to reproduce a fixed mockup height.
- Protection uses installed/current/stale/unobservable states, read-only mandatory categories and actual Android counters. It does not reproduce illustrative green totals or imply complete protection.
- Terms display supported excerpts and uncertainty from the real analyzer. Selection-only and seller/currency limitations occupy visible space instead of illustrative assurances.
- Space cards use local icons and minimal explicitly saved metadata. They do not fetch preview imagery. Parking organizes tabs without promising engine unload or form restoration.

Opaque token-pair contrast calculations and target sizes are in [DESIGN_SYSTEM](../DESIGN_SYSTEM.md). Both themes and widths320/390/430/768/1024/1440 were exercised in the production-widget test renderer, including200% text checks. Runtime images are separately labeled. No whole-app assistive-technology certification, frame-time, startup latency or leak measurement is inferred from these renders.
