# Spaces and Finish Mode implementation

Implemented on 2026-09-25 against the existing consumer session and policy system. References inspected: `03-spaces.png` and `04-focus.png` from the selected implementation kit.

- Spaces retain the three supported kinds, local notes, accessible reorder, create/rename/delete, offline resource IDs, and checklist editing. Details place saved resources and notes beside next steps on expanded layouts. Task association is explicit; creating a task from a Space copies the chosen notes/checklist. Deleting a Space detaches its tasks without deleting them.
- Workspace schema 2 migrates schema 1 in memory without changing the source document. The first successful explicit write commits the migrated document. Unknown fields, invalid nested collections, duplicate IDs, oversized documents, unsafe addresses, and invalid timers fail validation; failed writes preserve the prior snapshot and can be retried.
- Explicit normal-session URL saves are separate `SavedWorkspacePage` records, bounded to 50 per Space/task and 4,096 characters per address. Only canonical public HTTP(S) addresses are stored; the card label is the hostname. Credentials, fragments, search-provider/query-history addresses and sensitive query parameters are excluded. No page text, title, screenshot or remote preview is fetched. The caller supplies current policy/capability checks, and save/open revalidate. Saved data never supplies an allow decision. A queued page save also checks the captured originating tab/page before writing.
- Native URL saves are distinct from native history/form state and offline resources. Reopening an explicit saved address goes through the normal policy gate. It does not restore native back/forward history, scroll or forms. Private sessions cannot create durable URL saves; private notes/tasks and focus preferences remain in the existing ephemeral store.
- Optional timers offer 15/25/45 minute presets and custom 1–180 minute durations. Elapsed foreground time comes from a monotonic stopwatch, not decrement-only ticks or wall-clock deadlines. Pause/reset/resume are explicit. The app lifecycle background callback pauses the timer at a durable checkpoint; restart restores paused. Device sleep relies on the platform delivering its lifecycle callback; native sleep acceptance is tracked separately. Abrupt termination before a checkpoint can restore the last saved remaining duration. Timer expiry never completes a task or changes protection.
- Parking changes only memory-held organization markers on existing session tabs. It does not unload or close engines. Unpark is reversible. The existing engine retention limit can still evict a renderer; native history, scroll and forms are not promised after eviction or restart. Parking never crosses normal/private sessions.
- Optional distraction nudges default off and only use up to 20 explicit exact hostnames. The shell must evaluate mandatory protection first. Continue/dismiss suppresses the chosen hostname for the captured task in that session; pausing focus does not change mandatory protection. No history inference or cloud service is added.

## Validation

`flutter analyze --no-pub lib/signature/workspaces test/signature/focus_saved_pages_test.dart test/signature/workspace_redesign_layout_test.dart` passed with no issues.

`flutter test --no-pub test/signature/focus_saved_pages_test.dart test/signature/workspace_redesign_layout_test.dart test/signature/workspace_restoration_test.dart test/signature/workspace_state_test.dart --reporter expanded` passed 58 tests. Coverage includes migration/failure retry, corruption, private separation, timer background/restart/clock behavior, save eligibility and queued ownership, nudge dismissal, parking, actual SQLite document boundaries and task-owned closure/undo. The layout tests exercise both Spaces and Finish at 320/390/430/768/1024/1440 logical pixels with 200% text.

The focus caption moves below its timer ring at large text sizes, and wide columns stack at 200% text. These are deliberate accessibility adaptations. Light/dark appearance follows the app preference; focus does not force the whole application into dark mode.

Native engine enforcement and screenshot/build evidence are tracked separately in the main redesign acceptance matrix; unit/widget success does not certify native browsing.
