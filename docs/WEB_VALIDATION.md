## Reproducible SQLite/IndexedDB probe

The browser-only probe at `test/web/storage_probe.dart` is separate from the
production entry point and uses a dedicated `wingman_storage_smoke.db` database
with synthetic `example.com` records. It checks actual SQLite and IndexedDB,
not a mock repository.

```sh
flutter build web --release -t test/web/storage_probe.dart --output work/web-storage-probe
python3 -m http.server 8788 --bind 127.0.0.1 --directory work/web-storage-probe
```

Open `http://127.0.0.1:8788` in Chrome. The initial pass writes a normal tab, a
private tab, history, a bookmark, and preferences through the real repository.
It closes/reopens SQLite and checks:

- Only the normal tab and normal history are restored.
- Private URL, title and active-tab ID do not appear in restored data.
- Bookmark, Dark appearance and Brave Search preference are restored.

Reload the entire Chrome page to check IndexedDB durability across a fresh Dart
application instance. The probe must show an additional “PASS: browser reload
retained settings, bookmark, normal tab and history” result.

The initial open/reopen probe and full browser reload were both observed passing
in Chrome on the date above. The probe is a manual browser smoke application,
not a claim of a fully automated mobile/browser integration suite.

## Local storage properties and limits

`web/sqflite_sw.js` and `web/sqlite3.wasm` are bundled runtime files generated by
`dart run sqflite_common_ffi_web:setup` with the locked package versions.
The worker persists to browser-managed IndexedDB for the current origin.
Different local ports have different stores. Browser storage cleanup/eviction
can remove records. The upstream web adapter remains labeled experimental;
mobile uses native SQLite. No Wingman server stores these records.

History stores the most recent visit for each normal HTTP/HTTPS URL, for at most
90 days and 5,000 URLs. Settings, bookmarks and tab metadata have separate tables.
Private tab metadata and history are filtered at both state and SQL boundaries;
private bookmarking is disabled in this foundation. Private engine/site-storage
behavior is documented separately in `PRIVACY.md` and the native capability docs.

## Self-hosted web runtime and interface fonts

A follow-up network audit found Flutter's default release loader selected Google's
CanvasKit CDN and downloaded its default Roboto font. The final build now uses
`web/flutter_bootstrap.js` to resolve CanvasKit from `document.baseURI`, so it is
portable to a subdirectory deployment (`--base-href /wingman/`) without selecting
a runtime CDN. `scripts/check.sh` also passes `--no-web-resources-cdn` explicitly.

Roboto regular, medium and bold plus Noto Sans Symbols are bundled with their
Apache/SIL licenses (about 0.9 MB in total). Noto Sans Symbols is included in the
application theme's fallback families because the interface uses symbol glyphs.
Source URLs and file hashes are recorded in `assets/fonts/SOURCES.md`.

Flutter's standard conditional fallback remains enabled for other Unicode
scripts or emoji in Wingman's own saved titles. If a glyph is not covered by the
bundled fonts, Flutter can request the appropriate font subset from
`fonts.gstatic.com`. Such a request exposes normal technical network information
and a font identifier; Wingman does not send the text of a title or search query
as a font request. External mobile websites retain their normal website/OS font
behavior. This is not a claim of zero third-party traffic.

Pointing missing fallback fonts at an empty local directory was tested and
rejected: Flutter retries missing fonts repeatedly, creating 404s and poor
performance. A complete fallback package was estimated at approximately 21.9 MB
across 724 subsets/144 families. The final implementation keeps the interface
fonts local and preserves readable Unicode fallback without adding that payload.

The final uncached Chrome Home capture contained 15 completed HTTP requests, all
status 200 and all to `127.0.0.1:8787`. DevTools showed zero requests matching the
off-origin filter, plus one same-origin shared-worker connection marked pending
(not included among completed HAR entries). CanvasKit JS/WASM, all three Roboto
fonts and Noto Sans Symbols were visibly served from local URLs. A compact record
is in `WEB_RESOURCE_AUDIT.json`; the latest full sanitized test HAR remains in ignored
`work/web-home-handoff.har`. This observed Home capture is not a guarantee that
conditional Unicode fallback or the host browser never makes other requests.

Chrome showed no page errors after the final reload. The upstream Flutter engine
uses deprecated `Intl.v8BreakIterator`; Chrome advises `Intl.Segmenter`. The
selected stable SDK still uses that API. After enabling Flutter semantics and
using settings/search, DevTools also reported generated form fields missing an
id/name and verbose handler/reflow timing diagnostics. The console error and
warning categories were empty. No diagnostic was suppressed.
