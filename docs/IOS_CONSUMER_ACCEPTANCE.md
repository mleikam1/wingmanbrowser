# iOS consumer browser recovery verification

Date: 2026-09-11. Device selected: iPhone 17 Pro simulator, iOS 26.3 runtime (26.3.1, build23D8133), UDID `C157677F-A33F-45B2-BFFB-F3DED552D4F4`. Toolchain: Xcode 26.3 (17C529), iOS SDK 26.2. Ordinary target: `lib/main.dart`, consumer edition, bundle `com.wingmanbrowser.wingmanBrowser`.

## Implemented native behavior

`ProtectedWebBridge` now owns WKWebView directly. Normal tabs use `WKWebsiteDataStore.default()`; private tabs use separate nonpersistent stores. The supported element fullscreen API is enabled on iOS15.4+; WebKit still requires user interaction. Location uses WebKit/OS permission behavior with a when-in-use purpose string, and never requests background location. Normal JavaScript, first-party cookies, website storage, forms, native history, reload/stop, media requiring user interaction, origin-specific capture prompts, find, and an OS share sheet use supported WebKit/UIKit APIs. No script message handler or arbitrary page-to-native bridge is registered.

The native navigation delegate checks initial navigation, page/frame navigation, redirects, response destinations, new windows, and download redirects against the same SHA256-pinned mandatory domain/path baseline. Unknown consumer destinations are permitted under that policy. Provider navigation is rewritten to `safe.duckduckgo.com`; strict search enforces `kp=1` and `kac=-1`, blocks the documented DDG autocomplete endpoint, accepts normal punctuation and pagination, decodes known result wrappers once, and discards request bodies/headers when crossing a rewrite boundary. First/third-party functional resources use native WebKit networking. Mandatory domain/path rules and separate third-party tracker rules compile into cached `WKContentRuleList` chunks. The old exact-resource reader rule helpers remain only for isolated regression tests and are not attached to consumer views.

Native views survive inactive tabs, route overlays, app backgrounding, and media suspension. Explicit tab disposal, handoff lockdown, site-data deletion, and a change to additional restrictions release renderers. Tightening additional restrictions cannot race live page resources while replacement deny rules compile. Startup migration version 2 clears prior pilot data once and persists its receipt only after WebKit completes; later launches preserve new normal sessions.

Uploads bind the OS picker callback to the initiating renderer, document generation and origin; stale callbacks are denied. Main-frame uploads use an OS document picker (custom WKOpenPanel delegate on iOS18.4+, WebKit built-in behavior on earlier supported systems). Downloads require a user-triggered navigation, a separate filename/origin confirmation, a WKDownload delegate with destination and redirect checks, and an OS export picker. Temporary downloads are removed on picker completion/cancel, tab close, or next launch after a crash. They are never executed automatically. Renderer release also dismisses its owned file, share and JavaScript dialogs, resolving pending callbacks once (host regression passes late-action-after-cancel) so tab closure or handoff cannot leave a former page’s native dialog visible.

## Signed policy update path

The native channel supports `prepareConsumerPolicy`, `activateConsumerPolicy`, `discardConsumerPolicy`, and `revertConsumerPolicy`. Preparation verifies an Ed25519 envelope against keys shipped in the signed app, bounded metadata, app version, sequence, SHA256 and all mandatory categories, then compiles every replacement rule set while retaining the active policy. Activation requires the completed preparation token, saves the verified candidate and an atomic native receipt, releases existing renderers, and swaps the entire policy/rule set. The previous rules remain available for token-bound rollback. Reverting a merely prepared token leaves the current policy unchanged. An update receipt after restart gates browsing until Dart restores its verified cached release, preventing a temporary fallback to the weaker bundled baseline. Receipt corruption fails closed; signed data does not gain an allowlist exception.

The native receipt retains the highest accepted sequence and the previous acknowledged release. A restore may reuse only the acknowledged active or previous sequence/digest; ordinary update attempts must advance the high-water mark. Restoring the same active release preserves its predecessor instead of replacing it with itself. Native archive cleanup retains only the active, previous and currently reversible predecessor packages. Dart coordinates its own durable pending/active state with the native receipt. The bundled `consumer_update_keys.json` intentionally contains no production keys, so update capability reports unavailable until a real signing key and HTTPS feed are provisioned. Valid bundled protection remains usable offline. No browsing URLs, search queries, or per-destination lookup telemetry are sent to this update mechanism.

## Remaining limits and external dependency

Apple requires a managed `com.apple.developer.web-browser` entitlement to offer an iOS app as a system default browser. This checkout does not contain that Apple grant. HTTP/HTTPS incoming-link registration and native receiving are implemented, but `defaultBrowserAvailable` reports false. The build flag `WINGMAN_DEFAULT_BROWSER_ENTITLEMENT` must only be enabled together with the granted signing entitlement. Creating an entitlement file alone does not supply Apple's approval. See [Apple's default-browser requirements](https://developer.apple.com/documentation/xcode/preparing-your-app-to-be-the-default-browser).

No certificate exception API is implemented: authentication challenges use OS default handling. WebKit's fraudulent-website warning is enabled. HTTP web content is explicitly permitted using `NSAllowsArbitraryLoadsInWebContent`, as needed by an ordinary browser; this does not disable certificate validation or change native URLSession transport policy. A plain HTTP page is not claimed to be encrypted.

WebKit gates script popups through `javaScriptCanOpenWindowsAutomatically=false`; its approved new-window delegate then checks the destination before handing it to a tab. Complex POST new-window flows are not supported by this URL-only tab handoff. Arbitrary external schemes, file/data/javascript top-level pages, and blob downloads remain unavailable. Full PWA/service-worker behavior, media/fullscreen, camera/microphone, device authentication, real upload/export, and production entitlement behavior require physical-device testing. No blanket success claim is made for them.

Protection is URL/domain/path based and cannot classify every sentence, image, recommendation or advertisement. Top-level path checks decode and normalize path segments. WKContentRuleList resource path expressions match URL text; encoded or dynamically assembled subresource paths are not claimed to receive identical normalization. These paths and mixed-content categories require continued coverage evaluation. Search-provider adult filtering does not supply gambling or the other mandatory category classifications. See `PROTECTION_COVERAGE.md` for baseline scope and dataset limits.
