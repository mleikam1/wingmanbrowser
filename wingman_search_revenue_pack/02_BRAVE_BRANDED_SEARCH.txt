PHASE 02 — REAL WINGMAN-BRANDED SEARCH
Apply the master prompt and phase 01 boundaries. Work in the existing Flutter app and its native navigation adapters, not a disconnected demo.

PROVIDER INTEGRATION
Implement GET https://api.search.brave.com/res/v1/web/search behind Wingman's secret-bearing gateway; follow BRAVE_API_CONTRACT.md. Do not implement the quickstart's LLM-context endpoint as the search-results UI. Revalidate current request/response schemas. As reviewed, the API uses X-Subscription-Token, supports q/country/search_lang/ui_lang/safesearch, web count <=20 and page offset 0..9. Offset is a page index, not an item offset. Always set safesearch=strict server-side. For the initial All view request result_filter=web and text_decorations=false; omit or disable summary/rich callbacks and unneeded extra snippets. This bounds the returned surface; do not claim these switches reduce the published per-request price. Parse web.results for Web Search and the top-level results array for the separate News Search endpoint. Provider booleans do not certify compliance with the entire Wingman policy. Clamp request sizes and validate language/country against supported values. Do not forward a caller-supplied provider URL, custom headers, arbitrary Goggles URL, or filter override. Only Wingman's reviewed signed/versioned policy can configure permitted reranking.
Treat links, snippets, HTML emphasis and provider metadata as untrusted. Decode/sanitize to text or a narrowly allowed markup subset. Reject script/data/file/internal/credential-bearing URLs; validate HTTPS destinations using the existing policy. Do not mark allowed results “verified safe.” Apply title/description/domain checks before render and recheck destinations at activation, redirects and supported subsequent navigation. Explain platform enforcement limits rather than claiming full content inspection.

PRIVACY AND RELEVANCE
A submitted query exists only in active request/session state. Do not store query histories server-side, hash them into analytics labels, or include them in exceptions. Local bookmarks require explicit user action; do not silently save query-bearing pages. Keep query text out of page titles, referers and share URLs by default where possible. Provide explicit share behavior with a warning that the shared URL contains the query. Do not preconnect to publishers, merchants, favicon services or ad partners merely to display results. Only approved first-party/licensed assets may load automatically.
Request-level Wingman protection checks must precede Brave calls. Distinguish prohibited intent from educational/recovery content. Maintain permitted research access; test “gambling addiction help” and legitimate health queries without serving sensitive-topic ads. Block direct attempts to lower safesearch through encoded URLs, query parameters, settings, private sessions or platform bridges. Keep organic relevance independent of advertiser bids. Any Goggles use must be documented, policy-reviewed and tested for relevance regressions; do not use it to sell organic rank.

USER EXPERIENCE
Retain the existing approved Wingman logo, color palette, typography and browser chrome. Build a responsive Wingman Search view with a real search field, All and News tabs, recognizable source domain, readable title/snippet, concise protection explanation, keyboard navigation, screen-reader semantics and working copy/open actions. Use provider data; never invent result counts, ratings, freshness, rankings or merchants. Images/Video can follow later behind independent rights/safety acceptance—do not ship fake tabs.
The address bar must distinguish an explicit navigable URL from a search. A normal URL navigates through the existing native protection without a Brave charge. Search enters the Wingman results view. Back restores transient results and scroll during the active session without duplicate ad impressions or paid calls. No remote autocomplete in this release. Local bookmarks/static safe suggestions can be used without network calls. Native app browsing remains native; the web companion cannot claim to filter the host browser's unrelated tabs.

NETWORK AND ECONOMICS
One explicit search-page request normally triggers one Brave call; a News-tab selection is a separately accounted request. Do not fetch all verticals or later pages automatically. Support More Results only on explicit activation and only when current API metadata says more are available. Deduplicate displayed overlap without additional hidden calls. Do not trigger paid traffic on every keystroke, widget rebuild, hot reload, tab resume or ad update. Keep current visible results only for necessary operational session use; reusable/shared caching requires documented rights.
Search should complete even when the ad service is disabled/slow/empty. Apply a bounded ad decision deadline and stable layout; do not block results waiting for ad fill. Private/managed contexts skip the ad path entirely. On empty results, filtered results, timeout, exhausted budget, or provider outage show distinct accurate states. Do not silently redirect to an unapproved provider or scrape a public search page. Maintain ordinary browsing/local features.

TESTS AND EVIDENCE
Add synthetic contract fixtures, stale/out-of-order response tests, cancellation tests, XSS/malicious URL fixtures, changed-country/language cases, explicit URL versus search, pagination limits, privacy transitions, ad-service failure and no-query-log tests. Use generation/request tokens to prevent responses from a previous tab/query appearing in a new or private session. Verify the actual application on supported Android/iOS simulators/devices and responsive web; do not substitute a reference HTML mockup. Count live test attempts and keep real results out of committed fixtures unless licensed.
Deliver code, screenshots from the real app with non-sensitive test queries, setup commands, measured performance, calls-per-search evidence, and known platform limits. Measure quality using a manually created synthetic benchmark, not retained consumer search logs.
