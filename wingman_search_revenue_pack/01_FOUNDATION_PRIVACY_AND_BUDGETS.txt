PHASE 01 — FOUNDATION, SECRETS, CONTRACTS, PRIVACY AND COST GUARDRAILS
Apply every instruction in 00_MASTER_CODEX_PROMPT.txt. Implement this phase in the actual Wingman checkout.

1. Establish the baseline. Record current branch/commit, dirty files, runtime targets, existing search paths, native policy enforcement, cloud inventory and content backend shape. Run the existing analyzer/unit suites without modifying personal-device state. Capture pre-existing failures separately. Identify historical docs that contradict current code. Do not change native browser engines as part of this milestone.

2. Create docs/BRAVE_INTEGRATION_DECISIONS.md and a machine-readable rights/config register. Record provider, agreement reference/date, approved application/domains/platforms, permitted web display, separate ad placement, source attribution, shared-news use, storage duration, CDN fan-out, media permissions, AI permissions, provider retention, and commercial contact. Unknown grants remain unknown/disabled. Business evidence can be stored privately with a nonsecret reference in source control; never publish a confidential agreement.
Use distinct operational gates for live search, cached news, remote media, live ads, partner demand and production billing. These flags control features, never the mandatory protection baseline. A local boolean without documented authorization is not evidence of rights. Build synthetic fixtures that function without paid calls.

3. Add backend/setup_brave_secret.py or an equivalent repository-consistent command. Use hidden interactive entry, reject empty/invalid inputs, and write only to an ignored owner-only local file for development. Reject symlinks and unsafe permissions. Production uses an approved Secret Manager reference and least-privilege runtime identity. Never put the key in a browser bundle, Flutter asset/dart-define, URL, terminal argument, HTTP response, crash report or screenshot. Generate .env.example with names only. Add secret scanning and tests that public assets contain no secret. Do not run live key verification repeatedly. The owner has already obtained an API credential; follow LOCAL_KEY_SETUP.md rather than restarting signup. Chat-shared credentials must not enter generated files. Use a replacement entered locally for ongoing development and production, and record only a nonsecret configuration status.

4. Introduce reusable provider adapters and contract DTOs. Keep secret-bearing request processing separate from read-only public news snapshot/media delivery and authenticated administration. Design request schema validation, body/response size ceilings, restrictive outbound hosts, bounded timeouts, safe parsing and versioned response contracts. Reject unsupported parameters; the server sets strict filtering. Do not rely on CORS or an embedded client secret as abuse prevention. Authenticate administrative and ingest operations. Public search gets proportionate abuse controls, not a login requirement.

5. Implement a durable transactional attempt/cost ledger. Keep accounting separate from result storage, with endpoint, environment, date bucket, attempt count, status class and money units only—no consumer query/URL. Atomically reserve before every dispatch. Reserve retries separately; uncertain/time-out attempts remain spent. A missing/corrupt ledger blocks further paid dispatch. Credential replacement, rollback or deployment cannot reset counters. Implement a provider-QPS limit shared across web/news workers and separate ceilings so news cannot consume the search allocation. Persist all ceilings; do not auto-increase them when free credits or a new API key appear. Reconcile estimated versus provider-billed usage privately. Brave currently documents that only successful responses are billed. Preserve a conservative attempt reservation for failures/unknown outcomes as a spending safeguard, but distinguish attempts, confirmed successes, estimated charges, reconciled billed charges and unknowns. Never label every transport failure as a confirmed charge or use refunded estimates to create unlimited retries.
Choose a datastore consistent with the approved deployment and test its contention/cost. Local SQLite is acceptable only for local development; ephemeral container storage is not a shared production ledger. For scale, any leased quota-block optimization must prove that the sum of reserved blocks never exceeds the global ceiling and stale workers cannot reuse budgets. Avoid network I/O inside retried database transactions.

6. Design a default fixtures-only profile and an owner-approved small live-test allowance. Treat any sample $25 development cap as a proposal, not spending authorization. START_CODEX_HERE.txt provides a specific two-request local smoke-test allowance when the owner executes it. This is not permission for unlimited live development or scheduled polling. Implement its durable attempt limit before dispatch. Disable implicit retries/pagination/autosuggest/prefetch. A budget alert is not a hard limit; enforce at dispatch. On 401/403 pause for operator intervention; honor 429/Retry-After; bound 5xx recovery. No multiple-account workaround. Never refund an uncertain attempt locally merely because the UI timed out.

7. Audit privacy at every boundary. Prefer POST for Wingman's search API. Configure Referrer-Policy: no-referrer, no-store on private/query-bearing responses, CSP, redacted error telemetry and no service-worker cache of searches. Do not send typed input before explicit submission. Strip end-user forwarding/cookie/auth headers before Brave calls. Validate whether framework, CDN, load-balancer, WAF and cloud logs capture request bodies, query strings, IPs or tokens. Retention exclusions are not proof that data was never initially processed/stored: document reality and eliminate collection where configurable. Do not disable required administrative audit logs; ensure they never contain consumer queries.

8. Tests must prove: no secret in builds/logs; no query in persistent state; N concurrent reservations cannot exceed N-budget; unknown outcomes consume allowance; rotation/restart preserves counts; auth failures do not loop; production accepts no loopback/debug endpoint; all permitted outbound calls are classified and budgeted.

Deliver actual code/tests plus docs/BRAVE_SETUP.md, docs/DATA_FLOW_AND_RETENTION.md, docs/SEARCH_COST_CONTROLS.md, a dry-run deployment plan, the rights register, and a phase status report. Do not deploy or purchase anything without the required owner authorization. Continue to fixtures-based phase 02 even when production credentials/rights are missing.
